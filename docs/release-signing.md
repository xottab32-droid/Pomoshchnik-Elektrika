# Подпись APK и обновления без потери данных

## Почему APK из GitHub Actions не устанавливался поверх предыдущего

Ранее CI публиковал `app-debug.apk`. У каждой новой виртуальной машины GitHub Actions создавался новый `~/.android/debug.keystore`, то есть **каждая сборка имела другую цифровую подпись**. Android не позволяет заменить установленный пакет другим APK с тем же `applicationId`, но неподходящей подписью. Удаление приложения устраняет конфликт, однако стирает локальные данные.

Дополнительно `versionCode` должен строго возрастать при каждом обновлении.

## Постоянный ключ владельца

Для `0.5.1-alpha` создан один постоянный ключ, **не хранящийся в публичном GitHub**.

- PKCS12, 4096-bit RSA, alias `pomoshchnik`.
- Ожидаемый SHA-256 отпечаток сертификата:
  `A8:73:D8:7D:F1:33:FB:47:50:AA:F9:A4:8C:1C:E6:39:1C:ED:58:F3:FF:5E:43:D3:A5:2C:13:43:D3:95:1A:FC`.
- Публичный отпечаток доступен для аудита, пароль и приватный ключ в репозиторий не попадают.

В настройках репозитория [Actions secrets](https://github.com/xottab32-droid/Pomoshchnik-Elektrika/settings/secrets/actions) владелец должен добавить **два Repository secrets**:

1. `ELECTRICIAN_SIGNING_KEYSTORE_BASE64` — содержимое `KEYSTORE_BASE64.txt` из приватного набора подписи (одна строка).
2. `ELECTRICIAN_SIGNING_PASSWORD` — содержимое `SIGNING_PASSWORD.txt` из того же набора.

**Приватный ZIP и .p12 нельзя коммитить, загружать в Issues или публиковать в Releases.** Сохрани приватный ZIP в двух защищённых местах. При утрате ключа штатное обновление уже установленных APK станет невозможным. Не пересоздавай ключ для каждого релиза.

## CI: что происходит при сборках

- Pull request: unit-тесты, debug сборка, проверка release-подписи *одноразовым тестовым ключом*, Android-инструментальные тесты. APK со случайной debug-подписью **больше не публикуются** для установки.
- Push в `main` / ручной `workflow_dispatch`: при наличии двух секретов CI собирает `app-release.apk` и проверяет сертификат через `apksigner` перед выдачей артефакта `pomoshchnik-elektrika-0.5.1-alpha-SIGNED-release`.
- Если секретов ещё нет, подписанный APK **не публикуется**. Это ожидаемая защита от выпуска неверно подписанного приложения.
- Новые версии должны сохранять `applicationId = ru.pomoshchnik.elektrika`, тот же ключ и повышать `versionCode`.

## Один последний перенос с прежних debug-версий

Нельзя безопасно заменить старый APK, подписанный утерянным случайным debug-ключом, новым подписанным APK: Android проверяет подпись, обходить её запрещено.

1. В существующем приложении экспортируй **каждый** нужный объект в JSON (можно отдельно).
2. Убедись, что файлы доступны в менеджере файлов.
3. После появления первого **SIGNED-release** удали старую debug-версию.
4. Установи подписанную версию и импортируй проекты JSON.
5. Следующие подписанные выпуски с тем же ключом и новым `versionCode` должны обновляться поверх предыдущих **без удаления данных**.

Не удаляй предыдущую версию приложения, пока подписанный APK не создан и копии объектов не сохранены.

## Открытость и безопасность

Подпись APK важна именно для доверенной доставки обновлений: исходники могут быть публичными, а приватный ключ обязан оставаться секретным. CI проверяет публичный отпечаток ожидаемого сертификата; проверка не доказывает воспроизводимость сборки и не заменяет аудит исходников.

Позднее для встроенного обновления приложения потребуется отдельная функция обнаружения релиза, скачивания APK с проверкой SHA-256 и запуск системного установщика Android. Автоматическая установка без согласия пользователя не предусмотрена.
